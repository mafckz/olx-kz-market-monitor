# Настройка GitHub-доступа на другой машине

## Секреты и доступ

Этот файл намеренно не содержит паролей, personal access token (PAT), OAuth-токенов, cookies или содержимого локального хранилища учётных данных. Секреты привязаны к аккаунту и не переносятся в проект. Не запрашивай их у владельца в чате и не добавляй в Git, `.env`, командную строку или URL remote.

Публичное зеркало `mafckz/olx-kz-market-monitor` можно клонировать без входа. Основной репозиторий `grromankz-ctrl/olx-kz-market-monitor` приватный: для него владелец должен выдать доступ именно GitHub-аккаунту нового агента. Доступ к публичному зеркалу не даёт автоматически доступ к приватному.

В текущем рабочем окружении GitHub-доступ Codex и GitHub CLI были разными авторизациями: подключённая GitHub-интеграция читала и изменяла приватный репозиторий, а локальный `gh` был отдельно авторизован аккаунтом `mafckz` через системное хранилище учётных данных. Эта CLI-сессия не могла клонировать приватный `grromankz-ctrl` репозиторий, но могла отправлять изменения в публичное зеркало. Поэтому успешный вход в Codex не означает, что CLI уже авторизован так же, и наоборот.

## Область доступа: аккаунты, организации и репозитории

У GitHub нет единого переключателя «дать агенту полный доступ ко всему GitHub». Подключение относится к конкретному GitHub-аккаунту и/или организации, а не ко всем аккаунтам, организациям и проектам на платформе. Для GitHub App установка отдельно выбирает `All repositories` или `Only select repositories` внутри выбранного личного аккаунта либо организации. Даже при `All repositories` приложение ограничено разрешениями, которые оно запросило и которые были одобрены; организация может требовать одобрения владельца. Для Codex проверяй конкретное подключённое приложение и показываемые им аккаунты/разрешения: настройки CLI `gh` не расширяют полномочия интеграции Codex.

Если владельцу действительно нужен доступ нового агента ко всем текущим репозиториям определённой организации, сначала выясни тип интеграции. Для GitHub App её устанавливают отдельно в целевой организации или личном аккаунте; при установке выбирают `All repositories` только если приложение запрашивает права репозитория и GitHub показывает такой выбор, затем владелец организации одобряет запрошенные права, если это требуется. OAuth-авторизация пользователя — отдельное действие, которое может попросить Codex; сама по себе она не является установкой приложения и не всегда предоставляет переключатель `All repositories`. Для пользователя организации можно отдельно назначить роль с доступом ко всем репозиториям, если такой тип роли доступен в настройках организации и тарифном плане. Для личных репозиториев область установки настраивается отдельно в личном аккаунте владельца. Повторить настройку придётся для каждого целевого аккаунта/организации; к другим владельцам/организациям она не распространяется. Широкий доступ может позволить читать, менять или удалять данные в зависимости от разрешений, поэтому безопаснее выбрать только необходимые репозитории и минимальные права.

Создание репозитория — отдельное полномочие, а не автоматическое следствие чтения/записи в существующие репозитории. Пользователь должен иметь право создать репозиторий у выбранного владельца; организация может ограничивать создание репозиториев настройками. Кроме того, конкретная интеграция/агент должен предоставлять операцию создания и иметь соответствующее разрешение. CLI-команда `gh repo create` может создать репозиторий только в пределах разрешений авторизованного аккаунта и политик организации. Успешный `gh auth status` или видимость всех существующих репозиториев сами по себе не подтверждают право создавать новые.

Срез текущей GitHub-интеграции Codex (26.10.2026) показывает установленное приложение для личного аккаунта `grromankz-ctrl` с `repository_selection=all`; список коннектора содержит шесть репозиториев этого аккаунта, и у аутентифицированного пользователя отображается `admin` на каждом из них. Подключённой организации в списке установок нет. Это широкий доступ к репозиториям одного конкретного личного аккаунта, а не ко всем аккаунтам/организациям GitHub. В доступном наборе GitHub-действий нет отдельной операции создания репозитория, поэтому возможность создавать новые репозитории через этот коннектор не подтверждена. CLI `gh` — отдельный вход: ранее проверенный `gh`-аккаунт `mafckz` имел доступ к публичному зеркалу, но не к приватному репозиторию. Проверяй актуальную область и роли в интерфейсе перед работой: установки и права могут измениться.

## Подключение Codex

1. На новой машине войди в Codex под собственным аккаунтом.
2. В настройках подключённых приложений/интеграций Codex подключи GitHub под тем GitHub-аккаунтом, которому владелец выдал нужный доступ. Пройди OAuth-авторизацию, если её запросит Codex; если это GitHub App, отдельно проверь, что приложение установлено на нужный аккаунт/организацию и какие права/репозитории выбраны при установке.
3. Для чтения приватного репозитория владелец должен добавить этот аккаунт в `grromankz-ctrl/olx-kz-market-monitor` либо в команду/организацию, имеющую доступ. Для отправки веток понадобится право записи; если его не выдали, работай в форке и открой pull request. Если требуется доступ ко всем репозиториям, у GitHub App владелец выбирает `All repositories` для нужного аккаунта/организации только если GitHub предоставляет этот выбор. Для иных типов интеграции следуй фактическим настройкам Codex; не предполагай наличие такого переключателя. Это не даёт доступ к чужим аккаунтам/организациям.
4. Для создания новых репозиториев отдельно проверь, что у аккаунта агента есть право создания у нужного владельца и что Codex-интеграция/CLI предоставляет такую операцию с требуемым разрешением. Для организации попроси владельца проверить организационное ограничение на создание репозиториев. Не выдавай организационный Admin или владельца ради обычного clone/push, если достаточно репозиторной роли.
5. Проверь, что GitHub-интеграция видит именно необходимые репозитории и функции. Если приватный репозиторий не виден, попроси владельца проверить выданный доступ и подключённый GitHub-аккаунт; не пересылай чужой токен.

Названия и расположение пунктов настроек Codex могут отличаться между версиями приложения. Для работы только с публичным снимком GitHub-интеграция необязательна.

## Подключение GitHub CLI

Если агенту нужен `git`/`gh` в терминале, авторизуй его собственный GitHub-аккаунт локально через браузер:

```powershell
gh auth login --hostname github.com --git-protocol https --web
gh auth status
```

Заверши вход самостоятельно в открывшемся браузере. Не используй чужой пароль/PAT, `--with-token` или `--insecure-storage`. После входа обязательно проверь `gh auth status`: если системное credential store недоступно или завершилось ошибкой, GitHub CLI может автоматически сохранить токен в plaintext-файл. В таком случае не используй эту авторизацию для приватного репозитория: настрой поддерживаемое системное хранилище, повтори вход и проверь результат через `gh auth status`. Не копируй credential-файлы на другую машину.

Проверь доступ:

```powershell
gh repo view mafckz/olx-kz-market-monitor
gh repo view grromankz-ctrl/olx-kz-market-monitor
```

Первая команда проверяет публичное зеркало. Вторая сработает только после выдачи доступа к приватному репозиторию. Чтение и отправка изменений требуют разных уровней доступа: для push нужна запись; без неё используй fork и pull request. Если приватная команда сообщает, что репозиторий не найден или недоступен, сначала проверь `gh auth status` и попроси владельца выдать доступ нужному аккаунту. Не пытайся обходить проверку доступа.

GitHub CLI сохраняет токен в системном credential store, если он доступен; иначе возможен автоматический fallback в plaintext-файл. Проверяй фактическое место хранения через `gh auth status` и не полагайся только на отсутствие флага `--insecure-storage`. Если для автоматизации всё же требуется токен, создай отдельный минимально привилегированный токен под конкретный репозиторий, сохрани его только в поддерживаемом хранилище секретов и никогда не добавляй в файлы проекта. При утечке отзови токен в GitHub.

## Клонирование проекта

Для работы с публичным снимком:

```powershell
git clone https://github.com/mafckz/olx-kz-market-monitor.git
cd olx-kz-market-monitor
git switch main
git pull --ff-only origin main
```

Используй приватный remote только после того, как владелец подтвердил доступ твоему аккаунту. Не вставляй PAT в HTTPS URL remote.
