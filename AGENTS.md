# Правила и карта проекта

Перед работой прочитай [`codex-orcestration.md`](codex-orcestration.md), [`docs/task-workflow.md`](docs/task-workflow.md) и [`docs/tasks.md`](docs/tasks.md). Регистрируй содержательные задачи до реализации, соблюдай выбранный цикл и не отмечай задачу завершённой до независимого ревью и проверки критериев. Не запускай тесты, если пользователь явно не просил тестирование или проверку. Указывай подтверждённое состояние функций и автоматизации.

## Структура репозитория

```text
.
├── AGENTS.md
├── codex-orcestration.md
├── docs/
│   ├── adr/                 # Записи архитектурных решений
│   ├── implementation-plan.md
│   ├── requirements.md
│   ├── task-workflow.md
│   └── tasks.md
├── scripts/
│   └── setup.ps1            # Установка окружения и настройка Windows Scheduled Task
└── src/olx_monitor/
    ├── __main__.py          # Точка входа `python -m olx_monitor`
    ├── cli.py               # CLI-команды configure, run и once
    ├── setup_wizard.py      # Интерактивная локальная настройка
    ├── bot.py               # Telegram-команды, ответы и планировщик запусков
    ├── monitor.py           # Цикл поиска, обработка карточек и обновление истории
    ├── sources/olx.py       # HTTP-клиент OLX, разбор выдачи/объявлений и фильтры источника
    ├── profiles.py          # Разбор поисковых запросов и классификация совпадений
    ├── models.py            # Модели данных приложения
    ├── database.py          # SQLite-схема и операции чтения/записи
    ├── settings.py          # Настройки приложения и загрузка конфигурации
    ├── paths.py             # Пути локальных данных приложения
    ├── reporting.py         # Markdown-отчёты и сводки для Telegram
    ├── ai.py                # Необязательный анализ профиля поиска и объявления
    └── facts.py             # Анализ наблюдаемых фактов и объяснение признаков
```

В корне также находятся `pyproject.toml` (зависимости, пакет и CLI entry point), `README.md`, `GLOSSARY.md` и `.gitignore`. Игнорируемые окружение, кэш и генерируемые package metadata не являются исходниками приложения.

## Точки входа и потоки

- Команда `olx-monitor` зарегистрирована в `pyproject.toml` и ведёт в `olx_monitor.cli:main`. Эквивалентный модульный вход — `python -m olx_monitor` через `__main__.py`.
- `olx-monitor configure` вызывает `setup_wizard.configure` для интерактивной конфигурации.
- `olx-monitor once` создаёт настройки и SQLite базу, запускает один цикл `Monitor.run`, печатает сводку и сохраняет Markdown отчёт без Telegram polling.
- `olx-monitor run` запускает Telegram-приложение из `bot.run_bot`; бот обрабатывает запросы пользователя и плановые проверки через `Monitor`.
- Основной поток мониторинга: активные профили → `OlxClient.search` → `Monitor` фильтрует город и цену с помощью `within_price`/`city_matches` из `sources/olx.py`, затем классифицирует карточки через `profiles.py` → для нужных карточек запрашивает детали и выполняет детальную классификацию, собирает признаки через `facts.py` и при AI-режиме анализирует их через `ai.py` → сохраняет карточки, детали и события через `Database` → `reporting.py` формирует Markdown-отчёт и digest.
- `scripts/setup.ps1` устанавливает пакет и по выбранным параметрам вызывает настройку или создаёт Windows Scheduled Task для команды запуска.

Карта основана на текущих файлах и точках вызова; после переименования или перемещения модулей обнови этот раздел.
